# F-01 authentication verification

Verified locally on 2026-11-06 on `feature/01-authentication`, based on Sprint 1 staging commit `b03f364`. The PostgreSQL instance ran on loopback with separate synthetic development and test databases.

## Test-first evidence

Before implementing the routes, `npm run test:unit -w server -- tests/auth.test.ts` returned exit code 1. Vitest reported `1 failed` file and `8 failed` tests. The requests reached Express and returned `404` because F-01 routes were absent. For example, the seeded Student login assertion reported `expected 404 to be 200`.

After implementation, `npm run build` exited 0 and built the server and client. Vite emitted warnings about React Router's `"use client"` directives. `npm test` exited 0 and reported `7 passed` files and `36 passed` tests, including all eight HTTP contract tests and the PostgreSQL authentication integration test.

| Acceptance criterion | Verified result |
|---|---|
| AC-01 / TEST-01 | Student login returned safe identity and set an HTTP-only, SameSite=Lax session cookie. PostgreSQL held the corresponding session row. |
| AC-02 / TEST-02 | Supervisor login returned the Supervisor role. The production cookie option added Secure. |
| AC-03 / TEST-03 | Incorrect credentials returned a generic 401 for both known and unknown emails and created no session. |
| AC-04 / TEST-04 | Current-user returned the stored identity. Logout deleted the session. Replay and expiry at the TTL boundary returned 401. |
| AC-05 / TEST-05 | The seeded PostgreSQL row contained a bcrypt hash that matched the synthetic test password. |
| AC-06 / TEST-06 | Tested strict JSON validation, ignored redirect query input, session rotation, tamper rejection and ignored role cookies. The timing sample below compared the two invalid-credential paths. |
| AC-07 / TEST-07 | Concurrent failed attempts, password spraying and general API bursts triggered 429 with Retry-After. Login recovered after the failure window. |

## Browser smoke check

Applied the migration with `npm run db:deploy -w server`, seeded the synthetic development database with `npm run db:seed`, and started the app with `npm run dev`. A local Playwright smoke script drove headless Chrome through the client, Express and PostgreSQL.

- Opening the Student home without a session led to login. Empty fields showed inline errors, and a wrong password showed the generic error.
- Each seeded role reached its own home after signing in. Reload restored the session, and requesting the other role's URL returned the user to their own home.
- Sign-out returned each role to login, removed the browser cookie and left `GET /api/auth/me` returning 401.

## Local SEC-07 sample

Measured 30 HTTP login attempts each for a registered and an unknown email, alternating request order after warm-up. An injected clock advanced the throttle window between pairs. All responses returned 401 with the same body.

| Input | Median | p95 |
|---|---:|---:|
| Registered email, wrong password | 55.35 ms | 56.91 ms |
| Unknown email, wrong password | 55.31 ms | 56.25 ms |

These measurements cover the local seeded configuration. The Sprint 1 security suite and release acceptance checks remain separate.
